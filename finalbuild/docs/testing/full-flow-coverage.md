# Cross-platform full-flow test matrix

This matrix tracks the diagnostic journey shared by backend, Desktop, Android and native iOS. It separates deterministic unit tests from live-device/emulator tests; passing a unit test does not claim a physical OBD adapter was exercised.

## Canonical flow
1. Create a session and choose/modify a vehicle.
2. Add, edit and remove a symptom.
3. Add and edit a DTC; verify normalization and session identity.
4. Run analysis and verify hypotheses remain evidence-based (no unsupported confirmed component failure).
5. Read the decision plan/recommendations.
6. Record a test result with notes/measurements and verify the updated session can be read back.
7. Exercise invalid URL, backend error, unknown session and offline/error handling.
8. Verify EN/RU/HY language selection and preserve the selected language in analysis/result requests.

## Automated coverage added in this change

| Layer | Test coverage added | CI execution |
|---|---|---|
| Backend/API | Full session lifecycle: create, symptom update, DTC update, analysis, recommendation test result, reload; unknown-session read | `pytest -q` and backend coverage gates |
| Desktop | Client-level happy path across create → DTC → evidence → analyze → decision plan → record result; verifies endpoint order and payloads; unknown-session error is surfaced | `pytest -q apps/desktop/tests` with the existing 95% focused-client/model/storage gate |
| Android | Repository tests for catalog, create/update vehicle, symptom add/update/delete, DTC normalization/update, analysis language and recording a test result | `./gradlew testDebugUnitTest assembleDebug` |
| Native iOS | Invalid backend URL, malformed URL and HTTP 503 error paths; existing suite covers session workflow, vehicle, symptom/DTC operations, analysis, test results and localization | Native iOS workflow runs the Xcode test target |

## Expected diagnostic invariants
- User-reported symptoms and DTCs are preserved with the correct session.
- DTC codes are normalized to uppercase on Android.
- Analysis can return multiple hypotheses; a possible hypothesis must not be presented as a confirmed component failure without supporting evidence.
- Test result status, notes and measurements are carried through the API.
- Backend errors are surfaced to the user/client and must not be converted into a fake successful response.
- Unit tests use mocks/fakes where appropriate; they do not prove BLE/USB/Wi-Fi communication with a physical adapter.

## Coverage policy
Backend critical diagnostic packages retain the configured 90% minimum gate. Desktop's focused API/model/storage scope retains its 95% gate. These percentages apply only to the paths named in CI and must not be described as whole-application coverage. Android and iOS coverage percentages are reported only when their respective coverage instrumentation is generated by CI; a successful build or passing tests alone is not a coverage percentage.

## Commands
From `finalbuild/`:

    pip install -r backend/requirements-dev.txt
    pytest -q
    pytest -q --cov=backend --cov-report=term-missing --cov-report=xml

Desktop:

    pip install -r apps/desktop/requirements-dev.txt
    QT_QPA_PLATFORM=offscreen pytest -q apps/desktop/tests --cov=apps.desktop.api_client --cov=apps.desktop.models --cov=apps.desktop.storage --cov-report=term-missing --cov-fail-under=95

Android:

    cd apps/mobile-android
    ./gradlew testDebugUnitTest assembleDebug

Native iOS is tested by the repository's macOS/Xcode workflow; run the same Xcode scheme locally on macOS to reproduce it.
